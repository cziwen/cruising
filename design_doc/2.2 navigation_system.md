# 2.2 导航系统（Navigation System）

## 2.2.1 概述
导航系统负责管理港口之间的航行，包括距离计算、航速计算、航行进度显示等。系统基于距离（节）和当前航速来计算航行时间和进度。

## 2.2.2 核心要素

### 距离定义
- **单位**：节（knots）
- **换算关系**：8节 = 每小时（真实时间1秒）的形式距离
- **港口距离**：每个港口包含 `distances` 映射（目标港口ID → 距离（节））
- **示例**：192节 = 24小时（基础航速8节时）

**区域经济特质：**
- **西北海域**：由 [H] 和 [p1] 组成，是玩家的起点，主要产出基础建材（木材）。
- **中央贸易带**：[p2] 为核心，连接 [p3] 香料港，是初中期套利的主要区域。
- **东南工业/奢侈品区**：[p4], [p5], [p6], [p7] 构成的高价值环线。
  - [p4] 铁炉岛与 [p6] 翡翠领形成 **金属/石材 <-> 食物/酒** 的强互补。
  - [p5] 织梦湾与 [p7] 远古遗址是高价值轻工业与奢侈品的集散地。

### 航速计算
- **基础速度**：8节
- **水手加成**：根据水手技能计算，转换为节数
- **天气修正**：根据当前天气调整（+1节、0节、-2节）
- **最终速度**：基础速度 + 水手加成 + 天气修正（最小1节，无上限限制）

### 航行进度计算
- **总距离（节）** = 本次航行的目标距离
- **已航行距离（节）** = 离开港口以来的总累积里程（`accumulatedDistance`）
- **本段进度** = (`已航行距离` - `本段起点里程`) / (`总航程点` - `本段起点里程`)
- **剩余距离（节）** = `总航程点` - `已航行距离`
- **剩余时间（游戏小时）** = 剩余距离（节） / 当前航速（节）

### 时间换算
- **航行中**：1现实秒 = 1游戏小时（基于昼夜系统的时间比例 `cruisingTimeScale = 60.0`）
- **在港口**：1现实秒 = 1游戏分钟（基于昼夜系统的时间比例 `portTimeScale = 1.0`）
- 如果航速是8节，1现实秒 = 8节的距离
- 如果航速是10节，1现实秒 = 10节的距离
- **时间系统**：详见 `2.8 day_night_system.md`（时间比例）

## 2.2.3 航行流程

### 选择目的地
1. 玩家在港口界面或在海上（无目标港口）→ 点击"选择目的地"按钮
2. 打开**交互式世界地图对话框** (`_MapPortSelectDialog`)：
   - **背景**：显示一张完整的世界大地图 (`assets/images/world_map/world_map.png`)。
   - **坐标映射**：港口在地图上的位置由 `ports.json` 中的 `mapX` 和 `mapY` 字段配置。
   - **交互反馈**：点击港口图标会选中该目的地，并在其上方显示一个动态的红圈 (`assets/images/world_map/red_circle.png`)。鼠标悬停在港口上时仅有轻微的颜色变红反馈。
   - **过滤规则**：玩家可以随时选择任何已解锁的目的地。在海上时，不再过滤掉“海上”特殊地点或上一个出发港口，允许玩家进入无尽航行或中途折返回港。
3. 显示每个港口的信息：
   - 港口图标（普通港口为定位图标，海上地点为波浪图标）
   - 港口名称标签
   - 当前港口使用 orange 色高亮标记
4. **出发决策**：地图右下角显示“出发”按钮。只有在玩家选中了一个非当前港口的目的地后，该按钮才变为可点击状态。
5. **坐标调试支持**：在调试面板开启“地图坐标调试”后，地图上会显示十字准星及鼠标当前的原始坐标（相对于 1344x768 背景图），方便开发者调整 `ports.json` 中的 `mapX` 和 `mapY`。
6. 玩家在地图上选择港口后点击“出发”按钮 → 关闭地图，开始航行

### 开始航行
1. 离开当前港口，进入海上状态
2. 获取航行距离（节）
3. 初始化进度计算（总距离、已航行距离）
4. 开始实时更新进度

### "海上"特殊地点
- **用途**：让玩家离开港口进入海上状态，但没有目标港口
- **特点**：
  - 不是真正的港口，没有贸易功能
  - 选择后立即进入海上状态，`totalTravelDistance` 设置为无限大（`999999999`），确保玩家可以一直在海上航行
  - 玩家在海上时可以随时选择新的目的地
- **距离计算**：
  - 如果 `_previousPort` 为 null（如新游戏开始或特定重置情况），到目的地的默认航行距离 fallback 为 **240 节**。
  - 如果 `_previousPort` 不为 null，则所有非“海上”目的地的最小航行距离被强制设定为 **480 节**（包括从海上折返回到同一个港口）。
  - 从“海上”选择其他港口时，默认使用 `_previousPort` 到该港口的距离配置。
- **平滑退出逻辑**：系统采用“里程表模式”。当玩家在海上切换目的地时，`accumulatedDistance` 不会归零。由于 `exitOffset` 始终基于总里程计算，因此旧港口会持续平滑地滑出屏幕，不会发生闪现。进度条的 0% 起点则由 `legStartDistance` 字段记录。

### 航行过程
1. 顶部显示航行进度条。
2. **进度条样式**：采用像素艺术风格的自定义进度条 (`PixelProgressBar`)。
    - **背景板 (Holder)**：使用 `assets/paper_ui/Sprites/Content/5_Holders/` 路径下的素材 (9, 10, 11) 构建装饰性框架。注意：背景板中部的颜色可能与进度填充颜色相近。
    - **进度条 (Bar)**：使用 `assets/paper_ui/Sprites/Content/3_Progress_Bars/` 路径下的 `clean` 系列素材。
3. 显示目标港口名称。
4. 显示剩余时间（格式：X天Y小时）。
5. **实现机制**：通过 `CustomPainter` 进行双层叠加绘制：
    - **底层（空进度）**：使用素材 13_clean, 14_clean, 15_clean 铺满整个进度条。
    - **顶层（满进度）**：根据进度比例，使用素材 10_clean, 11_clean, 12_clean 覆盖在底层之上。
    - **视觉注意**：由于 Holder 的中段颜色与“满进度”素材颜色接近，可能会产生进度条没有更新的错觉，因此底层空进度建议设置一定的透明度（如 0.5）来增强对比。
6. 进度条实时更新（每帧更新，通常 60fps）。
6. 使用 dt 增量方式更新，确保平滑流畅。
7. **视觉反馈**：航行位移 (`totalSailingOffset`) 被实时累加到 `GameState` 中，用于驱动所有背景层和波浪层的水平滚动动画，模拟船只破浪前行的视觉效果。**滚动速度与当前航速成正比**，基础航速（8节）对应基础滚动速度（50像素/秒）。
8. **动态调整**：如果航速在航行中变化（例如天气变化），剩余时间会重新计算，且背景滚动速度也会同步调整。

### 到达港口
1. 进度达到100%
2. 触发场景切换动画
3. 切换到目标港口
4. 更新游戏状态

## 2.2.4 技术实现

### 进度更新机制
- 使用 `Ticker` 每帧更新进度
- 计算实际时间增量 dt（秒）
- 转换为游戏内时间增量（航行中使用 `cruisingTimeScale = 60.0`，即 1现实秒 = 1游戏小时）
- 累积游戏内时间
- **增量式里程计算（里程表模式）**：计算本帧行驶距离 = 当前航速 × 游戏内时间增量，并累加到 `accumulatedDistance` 中。这种方式确保了当航速突然变化（如天气或事件影响）时，总里程平滑增长，不会发生位置跳变。
- 计算进度 = (已航行距离 - 本段起点里程) / (总航程里程 - 本段起点里程)

### 状态管理
- `totalTravelDistance`：总航行距离（节）
- `accumulatedDistance`：已航行距离（节）
- `travelProgress`：航行进度（0.0-1.0）
- `remainingTravelHours`：剩余航行时间（游戏小时）

### 动态航速支持
- 航速可能在航行中变化（天气变化、船员变化）
- 每次更新进度时重新获取当前航速
- 剩余时间会根据新的航速重新计算

### 进度条渲染优化
- **资源预加载**：在 `GameScreen` 启动时显式加载进度条所需的所有像素切片，防止航行开始时因异步加载导致的显示延迟。
- **同步渲染**：`PixelProgressBar` 采用静态缓存机制，确保一旦素材加载完成，组件挂载时即可立即同步渲染。
- **视觉修正**：严格遵循像素艺术规范，进度条采用双层渲染。由于 Holder (5_Holders/10.png) 的中段底色与满进度素材 (10_clean - 12_clean) 视觉上非常接近，容易产生未更新的错觉。因此，底层空进度素材（13_clean - 15_clean）统一设置了 0.5 的透明度，以增强与 Holder 背景及满进度前景的对比。

## 2.2.5 数据模型

### 港口（Port）
- `id`: 港口唯一标识
- `name`: 港口名称
- `distances`: 距离映射（目标港口ID → 距离（节））
- `getDistanceTo()`: 获取到目标港口的距离（节）
- `isSeaLocation`: 是否为"海上"特殊地点（布尔值，默认为 false）
- `mapX`: 在世界地图上的 X 坐标比例
- `mapY`: 在世界地图上的 Y 坐标比例

### 航行状态
- `currentPort`: 当前港口（null表示在海上）
- `previousPort`: 上一个港口（用于从海上选择其他港口时计算距离）
- `destinationPort`: 目标港口（航行时使用，null表示在海上但没有目标）
- `isAtSea`: 是否在海上
- `isTransitioning`: 是否正在切换场景
- `totalTravelDistance`: 当前航行的终点里程（节）
- `accumulatedDistance`: 自离开港口以来的总航行距离（节，类似于里程表）
- `legStartDistance`: 本次航段开始时的总里程点（节）。用于确保进度条从 0% 开始计算。
- `travelProgress`: 航行进度（0.0-1.0），计算公式：`(accumulatedDistance - legStartDistance) / (totalTravelDistance - legStartDistance)`

## 2.2.6 与其他系统的关系

### 场景系统
- 导航系统负责计算航行进度和时间
- 场景系统负责背景切换和动画效果
- 两个系统协同工作：导航系统计算完成后，触发场景系统进行切换
- **参考**：`2.6 scene_system.md`

### 昼夜系统
- 航行时时间继续流逝（由昼夜系统管理）
- 时间倍数可能影响航行进度（如果基于游戏时间）
- **参考**：`2.8 day_night_system.md`

### 海上随机事件系统
- **“海上”无尽航行进度**: 在没有目标港口的“海上”状态下，航行进度 (`travelProgress`) 会随航行距离逐渐增加并最终维持在 `0.5`。这一机制确保了在无尽航行状态下，系统仍能正常判定并触发海上随机事件。
- **参考**：`2.18_sea_event_system.md`
