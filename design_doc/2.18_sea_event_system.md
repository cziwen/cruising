# 2.18 海上随机事件系统设计文档 (Sea Event System)

## 1. 系统概述
海上事件系统旨在增加航行过程中的随机性、互动性和策略深度。系统通过随机触发不同类型的事件（即时通知或交互决策），填补玩家在港口间航行的“空闲时间”，并根据玩家的选择产生实时的风险与回报。

## 2. 核心架构

### 2.1 数据模型 (Models)
- **SeaEvent**: 事件主体，包含标题、描述、类型（通知/决策）、触发概率、冷却时间和选项列表。
- **SeaEventChoice**: 事件选项，包含标签和一组效果。
- **SeaEventEffect**: 具体效果定义，如修改金币、耐久度、航行进度、速度倍率等。

### 2.2 核心逻辑 (Systems)
- **SeaEventSystem**: 
    - 负责加载 `sea_events.json` 配置文件。
    - 每一游戏小时进行一次触发判定。
    - 维护事件冷却时间 (Cooldown) 和单次航行触发限制。
    - 处理玩家选择并执行对应的效果逻辑。
- **GameState 集成**:
    - 在航行循环 (Travel Ticker) 中调用事件检查。
    - 提供 API 供事件系统修改船只状态、金币、进度等核心数据。
    - 管理视觉效果标志位（如风暴滤镜）。

### 2.3 最近港口搜索逻辑
- **坐标判定**：系统支持基于地图坐标 (`mapX`, `mapY`) 搜索最近的已解锁港口。
- **位置估算**：
    - 在航行中，根据 `_previousPort` 和 `_destinationPort` 的坐标，结合 `_travelProgress` 进行线性插值，估算当前位置。
    - 在无尽航行中，若 `_destinationPort` 为空，则以 `_previousPort` 为基准位置。
- **回退机制**：若无法获取有效坐标（如新游戏直接在海上开始），系统会默认选择列表中第一个已解锁的港口作为“最近港口”。
- **最小航行距离保护**：当事件（如暴风雨）导致航向改变并转向最近港口时，系统会自动应用 **480 节** 的最小航行距离限制。这确保了即便目标港口在地理上非常近，玩家仍有足够的航行时间来观看完整的入岛环境切换动画。

## 3. 触发机制
1. **触发窗口**: 默认在航行进度的 10% - 90% 之间触发。
2. **频率限制**:
    - 单次航行（港口 A 到 B）最大触发次数：3 次。
    - 事件特定冷却时间：触发后在指定的游戏小时内不再出现。
3. **判定流程**:
    - 每经过 1 游戏小时，系统从可用事件池中随机选择一个。
    - 进行概率判定（基础概率通常在 5% - 12% 之间）。

## 4. 事件类型与配置
所有事件通过 `assets/config/sea_events.json` 进行配置，目前包含以下核心事件：

| 事件 ID | 标题 | 类型 | 核心效果 |
| :--- | :--- | :--- | :--- |
| `sea_storm` | 暴风雨来袭 | 决策 | 损耗耐久换进度 vs 降速躲避 |
| `sea_merchant_ship` | 商船邂逅 | 决策 | 临时贸易 vs 忽略 vs 武力洗劫 |
| `sea_tailwind` | 顺风航行 | 通知 | 临时提升航速 |
| `sea_headwind` | 逆风航行 | 通知 | 临时降低航速 |
| `sea_distress_call` | 遇难求救信号 | 决策 | 营救（耗时获金） vs 搜刮物资 |
| `sea_reef_grounding` | 暗礁搁浅 | 决策 | 强行脱困（重损） vs 等待涨潮（耗时） |

### 4.0 本地化配置文件约定
- 默认文件：`assets/config/sea_events.json` (包含中文原文)
- 英文本地化配置：`assets/config/sea_events_en.json` (默认启动时加载)
- 语言切换时由 `GameConfigLoader` 按 `{filename}_{lang}.json` 优先加载，缺失时回退到默认文件。
- `SeaEventSystem` 在语言切换后应刷新事件缓存（调用 `updateLocalizations()`）以避免继续显示旧语言数据。

### 4.1 配置文件详解 (JSON Schema)

事件配置文件位于 `assets/config/sea_events.json`，是一个 `SeaEvent` 对象的数组。

#### SeaEvent (顶层字段)
- **id** (`String`): 唯一标识符，建议使用 `sea_` 前缀。
- **title** (`String`): 事件标题，显示在对话框顶部。
- **description** (`String`): 事件描述文本，支持使用换行符。
- **type** (`String`): 事件类型。
    - `notification`: 通知类，通常只有一个正面或负面的选项。
    - `decision`: 决策类，提供多个选项供玩家选择。
- **probability** (`double`): 每游戏小时的触发概率 (0.0 - 1.0)。通常设为 0.05 - 0.12。
- **cooldownHours** (`int`): 触发后的冷却时间（游戏小时）。在此期间该事件不会再次触发。
- **minProgress** (`double`, 可选): 触发所需的最小航行进度 (0.0 - 1.0)，默认 0.1。
- **maxProgress** (`double`, 可选): 触发所需的最大航行进度 (0.0 - 1.0)，默认 0.9。
- **assetPath** (`String`, 可选): 关联的视觉效果资源路径。在配置文件中也可以使用 `image` 字段，系统会自动映射。若配置且路径有效，对话框会显示该插图。
- **image** (`String`, 可选): 同 `assetPath`，作为事件插图的资源路径。建议统一存放在 `assets/images/events/` 目录下。
- **choices** (`List<SeaEventChoice>`): 玩家可选择的选项列表。

#### SeaEventChoice (选项字段)
- **id** (`String`): 选项唯一 ID。
- **label** (`String`): 按钮显示的文本。
- **condition** (`String`, 可选): 选项显示的前置条件。
    - `combat_unlocked`: 仅在战斗系统解锁后显示此选项。
- **effects** (`List<SeaEventEffect>`): 选择该选项后执行的效果。

#### SeaEventEffect (效果定义)
每个效果由 `type`, `value` 和可选的 `durationHours` 组成：

| type (类型) | value (值) 格式 | 说明 |
| :--- | :--- | :--- |
| `durabilityChange` | `int` 或 `[min, max]` | 改变船只耐久度（负值为扣除）。 |
| `goldChange` | `int` 或 `[min, max]` | 改变金币数量。 |
| `progressChange` | `double` | 增减航行进度（0.05 代表增加 5% 进度）。 |
| `speedMultiplier` | `double` | 航速倍率（如 1.5 为加速，0.7 为减速）。需配合 `durationHours`。 |
| `triggerCombat` | `String` | 立即触发战斗，value 为战斗场景 ID（如 `merchant`）。 |
| `changeDestination` | `String` | 更改航行目的地。目前仅支持 `nearest`（转向最近港口）。 |
| `addRandomGoods` | `int` 或 `[min, max]` | 随机获得指定数量范围的某种货物。 |
| `timeSkip` | `int` | 强制流逝指定的游戏小时数。 |

- **durationHours** (`int`, 可选): 仅对 `speedMultiplier` 有效，指定效果持续的游戏小时数。

### 4.2 新增事件模版
复制以下模版并填入内容即可快速新增事件：

```json
{
  "id": "sea_example_event",
  "title": "事件标题",
  "description": "这里是详细的事件描述文字...",
  "type": "decision",
  "probability": 0.1,
  "cooldownHours": 24,
  "minProgress": 0.2,
  "maxProgress": 0.8,
  "choices": [
    {
      "id": "option_1",
      "label": "积极选项",
      "effects": [
        { "type": "goldChange", "value": [50, 100] }
      ]
    },
    {
      "id": "option_2",
      "label": "风险选项",
      "condition": "combat_unlocked",
      "effects": [
        { "type": "durabilityChange", "value": -20 },
        { "type": "progressChange", "value": 0.1 }
      ]
    }
  ]
}
```

## 5. UI 与交互界面设计

### 5.1 界面布局 (Layout)
对话框采用堆叠布局，从上到下依次为标题区、插图区、描述区和选项区。整体使用纸张纹理作为背景。为了解决视觉溢出和比例不自然的问题，对各组件进行了精细化调整：

1. **标题优化**：背景图大幅增加内边距以实现等比例放大，文字使用黑色大字号并向上偏移，确保居中且不被背景边框遮挡。
2. **插图加载与 Fallback**：插图区不再仅仅是占位符。系统会优先尝试加载 `assetPath` 或 `image` 字段指定的图片。如果图片路径为空，则显示默认的图片占位图标；如果图片路径有效但加载失败（如文件缺失），则会通过 `errorBuilder` 显示一个“断开的图片”图标作为 Fallback，确保 UI 的稳定性。插图进行 0.8 倍等比例缩小，以平衡页面视觉中心。
3. **选项紧凑化**：选项按钮采用 `Align` 叠加技术（`heightFactor: 0.75`）实现深度重叠排版，同时增加按钮内部垂直边距以修复背景拉伸。
4. **位置上移**：通过底部 80px 的间距将选项区域整体向上推送，使其处于更易操作且视觉舒适的位置。

### 5.3 交互逻辑
1. **触发显示**: 满足触发条件时，`SeaEventSystem` 标记 `activeEvent`。
2. **对话框弹出**: `GameScreen` 监听系统变化，使用 `SeaEventDialog` 弹出全屏交互界面。
3. **逻辑暂停**: 对话框激活期间，游戏主循环中的时间流逝（昼夜系统）、航行进度累积、自动修理及战斗结算将自动暂停，确保玩家有充足时间进行决策。
4. **视觉反馈**: 
    - 特定事件（如风暴）会触发 `ScreenEffectLayer` 覆盖全屏灰色滤镜。
5. **效果结算**: 玩家点击选项后，系统立即执行效果并通过 `NotificationSystem` 提供反馈，随后关闭对话框、清除 `activeEvent` 并恢复游戏逻辑运行。

## 6. 系统集成点
- **与昼夜系统集成**: 使用游戏内小时数计算持续时间和冷却。事件激活时游戏时钟暂停。
- **与导航系统集成**: 基于 `travelProgress` 进行触发，并可直接修改进度和目的地。事件激活时航行进度暂停。
- **与战斗系统集成**: 部分决策选项（如洗劫商船）可直接调用 `startCombat()` 进入单场景战斗。事件激活时战斗逻辑暂停。
- **与存档系统集成**: 冷却状态和部分持续性效果支持序列化保存。

## 7. 多语言维护规范
为保证中英文事件内容一致，`sea_events.json` 与 `sea_events_en.json` 必须满足以下规则：

1. **结构一致**：事件数量、事件顺序、事件 `id`、选项 `id`、`effects` 结构必须完全一致。
2. **逻辑一致**：`type`、`probability`、`cooldownHours`、`minProgress`、`maxProgress`、`condition`、`effects` 数值不得因翻译被改动。
3. **仅文本差异**：允许差异的字段应仅限 `title`、`description`、`choices.label`。
4. **新增事件流程**：新增事件时先写中文，再同步补充英文；未完成英文前不应提交“可发布”状态。
5. **回归检查**：每次调整事件配置后，至少验证一次中英切换下的事件弹窗标题、描述与选项展示。
