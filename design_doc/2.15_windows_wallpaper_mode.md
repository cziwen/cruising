# 2.15 Windows 动态壁纸模式设计文档 (超宽屏 + 30 FPS)

## 1. 目标
将游戏转变为 Windows 平台的动态壁纸挂机游戏，支持超宽屏显示器，并锁定 30 FPS 以优化性能。

## 2. 技术实现

### 2.1 窗口嵌入逻辑 (Win32)
在 Windows 上，通过 `win32` 插件调用底层 API，将 Flutter 窗口句柄 (HWND) 设置为 `WorkerW` 的子窗口。

**关键步骤：**
1.  **查找 Progman 窗口**：获取桌面外壳的顶级句柄。
2.  **触发 WorkerW 创建**：向 `Progman` 发送 `0x052C` 消息，促使系统在壁纸层和图标层之间生成一个 `WorkerW` 窗口。
3.  **查找目标 WorkerW**：遍历窗口，找到紧贴在壁纸上方的 `WorkerW`。
4.  **设置父窗口**：使用 `SetParent(flutterHwnd, workerWHwnd)` 进行绑定。
5.  **窗口样式调整**：移除 `WS_CAPTION`, `WS_THICKFRAME` 等样式，使窗口全屏无边框。

### 2.2 超宽屏平铺算法 (Background Tiling)
为了在不拉伸背景图的情况下适配超宽屏（如 21:9 或 32:9），采用动态平铺技术。

**算法逻辑：**
- **计算需求数量**：`copyCount = (screenWidth / imageWidth).ceil() + 1`。
- **循环偏移**：
  - `currentOffset = -(gameState.totalSailingOffset * multiplier) % imageWidth`。
  - 在渲染循环中，依次放置 `N` 张图片，坐标为 `currentOffset + (i * imageWidth)`。
- **无缝衔接**：通过取模运算，确保图片在滚动出边界时立即重置到另一侧。

### 2.3 帧率限制 (30 FPS)
为了降低作为壁纸运行时的资源占用：
- **逻辑层**：`GameState` 中的 `updateWithDeltaTime` 保持不变（基于 dt），确保逻辑正确。
- **渲染层**：通过自定义 `TickerProvider` 或修改 `main.dart` 中的渲染循环，将 `Display Refresh Rate` 限制为 30Hz。

## 3. UI 适配原则
- **中心锚点**：船只始终处于 `screenWidth / 2` 处。
- **UI 布局**：
  - 交互按钮（如“市场”、“大厅”）相对于 `screenWidth / 2` 偏移，而不是锁定在 1920 坐标的固定比例。
  - 状态栏和进度条横跨屏幕底部或顶部。

## 4. 交互模式切换
- **壁纸模式**：置底显示，点击穿透（可选）。
- **交互模式**：窗口置顶或激活，捕获鼠标事件。
