# 2.5 UI系统（UI System）

## 2.5.1 概述
UI系统负责游戏的所有界面元素和交互。UI层包含状态栏、按钮、对话框等所有交互元素，支持响应式布局和动画效果。

**注意**：10层渲染系统的详细说明请参考 `2.6 scene_system.md`。本文档专注于UI层的组件和交互。

## 2.5.2 核心架构

### UI层位置
UI层位于渲染系统的最顶层（Layer 3），覆盖所有其他层：
- 位于场景层（背景、岛屿、船只）之上
- 处理所有用户交互
- 包含所有界面元素和按钮

## 2.5.3 界面组件

### 状态栏（StatusBar）
位于屏幕底部，单行分块显示游戏核心信息。

#### 布局结构
```
[ 💰1000 📍皇家港 ] [ 📦50/200 👥10/20 ] [ 🛠100/100 ⚙0.5/s ] [ 🎯1.2 ] [ ⛵12.5 ]
```

#### 显示内容
- **分块 1：基础资源**
  - **金币**：Icons.monetization_on 图标 + 数值，深黄色 (amber[900])。
  - **当前位置**：Icons.location_on 图标 + 港口名称，深褐色 (0xFF4E342E)。
- **分块 2：负载状况**
  - **载货量**：Icons.inventory_2 图标 + 已用/总量，深蓝色 (blue[900])。
  - **船员数量**：Icons.people 图标 + 当前/最大，深绿色 (green[900])。
- **分块 3：维护状态**
  - **船只耐久**：Icons.build 图标 + 当前/最大，深橙色 (orange[900])。
  - **修复速度**：Icons.build_circle 图标 + 数值/s，深橙色 (orangeAccent[700])。
- **分块 4：战斗力**
  - **炮火攻击力**：Icons.gps_fixed 图标 + 数值，深红色 (red[900])。
- **分块 5：机动性**
  - **航速**：Icons.sailing 图标 + 节数，深青色 (cyan[900])。

#### 样式特点
- **整体背景**：使用 `assets/images/ui/HUD_bot_bg_s.png` 纹理背景，固定尺寸为 814x65 像素（设计分辨率下）。
- **布局样式**：采用底部居中悬浮样式（Center + Row mainAxisSize.min），不再强制填满全屏宽度。
- **分块背景**：信息项按功能分组，每组使用基于纸张素材（9.png, 10.png, 11.png）的平铺背景包裹，形成独立的视觉模块。中段 `10.png` 采用横向平铺（repeatX）以适配变长内容。
- **同高约束**：`PaperHolder` 对 9/10/11 三段使用统一高度拉伸约束（`Row crossAxisAlignment.stretch` + `BoxFit.fill`），避免两侧与中段出现视觉高度不一致。
- **自适应布局**：根据屏幕宽度自动调整字体（14-18px）和图标（18-22px）大小。
- **板块间距**：板块之间保持 6 像素的横向间距；同组内两个数据项间距为 10 像素。
- **内边距**：外层容器使用 `EdgeInsets.symmetric(horizontal: 8)`，内部各分块使用 `EdgeInsets.symmetric(horizontal: 16, vertical: 8)`。
- **图标与文字颜色**：为了适应分块的浅色纸张背景，图标统一使用深褐色 (`0xFF4E342E`)，数值根据类别使用对应的深色调，确保高可读性。

### 动画时钟（AnimatedClock）
位于屏幕底部状态栏的左侧，通过动画帧显示大致的游戏时间。

- **位置**：底部居中，位于状态栏左侧。
- **背景**：使用 `assets/paper_ui/Sprites/Content/5_Holders/2.png` 纸质边框。
- **内容**：显示一个随时间变化的圆形时钟/天体图标。
- **动画帧逻辑**：
  - 将一天分为四个时段，每个时段 6 小时：
    - `1_Dawn` (黎明): 06:00 - 12:00
    - `2_Day` (白天): 12:00 - 18:00
    - `3_Noon` (正午): 18:00 - 00:00
    - `4_Night` (夜晚): 00:00 - 06:00
  - 每个时段文件夹包含 10 帧精灵图（1.png 到 10.png），每帧代表 36 分钟。
- **更新**：通过 `AnimatedBuilder` 监听 `GameState` 实时更新当前帧。
- **特点**：去除了数字显示，通过视觉图标（如日出、烈日、日落、明月等帧动画）暗示时间，增强沉浸感。精准数字时间已移至调试面板。

### 航行进度条
位于屏幕顶部，仅在海上航行时显示。

- **位置**：顶部（left: 100, right: 16，避免与时间显示冲突）
- **内容**：
  - 目的地名称和剩余时间（X天Y小时格式）
  - 自定义像素风格进度条 (`PixelProgressBar`)
- **样式**：基于 `paper_ui` 素材的双层渲染，底层透明度 0.5。
- **显示条件**：`isAtSea && totalTravelDistance > 0`
- **计算方式**：基于距离（节）和当前航速计算进度和剩余时间
- **参考**：详见 `2.2 navigation_system.md` (进度条样式部分)

### 自定义按钮 (PaperButton)
所有主要交互按钮均已替换为基于切片精灵图的自定义 `PaperButton` 组件，以匹配游戏的纸质 UI 主题。

- **实现机制**：使用 `assets/paper_ui/Sprites/Content/4_Buttons/Sliced/` 下的切片素材。背景由三段式结构组成：左侧固定端、中间重复段、右侧固定端。
- **样式映射**（三图一组，每种样式包含常态与按下两组素材）：
  - **样式 0 (棕色 brown)**：常态 `16-18.png` / 按下 `19-21.png` - 用于新游戏、设置或默认/取消操作。
  - **样式 1 (绿色 green)**：常态 `22-24.png` / 按下 `25-27.png` - 用于确认、出发或正面操作。
  - **样式 2 (蓝色 blue)**：常态 `28-30.png` / 按下 `31-33.png` - 用于读取存档、继续游戏或信息查询。
  - **样式 3 (红色 red)**：暂时回退到 `brown` 样式 - 用于删除、解雇或危险操作。
  - **样式 4 (金色 gold)**：暂时回退到 `brown` 样式 - 用于高亮或特殊功能。
  - **样式 5 (方形 square)**：无图片资源 - 纯色边框样式，用于数量微调按钮（如 ±1/±10）。
- **技术特点**：
  - **防拉伸背景**：背景通过 `Row` 组合三段图像实现。左、右端盖固定为正方形（宽度 = 按钮高度），中间段使用 `Expanded` 配合 `ImageRepeat.repeatX` 实现像素级的横向平铺。
  - **视觉冗余设计**：为了确保背景视觉上的饱满感，无论文本长短，背景宽度均会自动额外增加一个中间重复段的宽度（`_middleSegmentWidth = 12.0`），并同步增加水平内边距。
  - **最小尺寸约束**：按钮设有最小宽度约束（`height * 2.0`），确保即便在无文字情况下也能完整显示左右两个端盖。
  - 使用 `BoxFit.fill` 和 `FilterQuality.none` 保持像素艺术的清晰度，确保端盖与中段无缝衔接。
  - **动态缩放与换行**：
    - 当文本长度 > 8 个字符时，字体大小自动缩小 10%。
    - 当文本长度 > 9 个字符且包含空格时，自动在中间位置折行为两行，并显著缩小字体（缩小 25%），行高固定为 1.0 以保持紧凑。
    - 使用 `FittedBox` 进行二次保底缩放，确保文字永远不会超出按钮背景的视觉“清晰区域”。
  - 支持文本标签和图标的组合显示。
  - 通过 `GestureDetector` 实现即时的按压反馈效果。

## 2.5.4 对话框系统

### 基础组件：PaperDialog
所有游戏内业务对话框（交易、船员、船厂等）均基于 `PaperDialog` 构建。
- **背景**: 动态加载指定的纸张纹理图片（`4.png` 到 `7.png`）。
- **文字**: 默认使用深褐色 (`0xFF4E342E`)，模拟航海日志的墨水效果。
- **布局**: 自动处理安全内边距，确保内容不遮挡纸张边缘的磨损和撕裂效果。

### 交易对话框（TradeDialog）
显示基于物品交换机制的交易界面。
- **背景**: 使用 `7.png`（宽屏大型纸张）。
- **组件样式**: 
  - 物品格 (`GoodsSlot`) 采用浅棕色调，选中时高亮。
  - 交易天平使用木质感配色。
  - 文字颜色统一为深褐色。

#### 布局结构
详见 `2.1 trade_system.md` 中的界面设计部分。采用四栏布局：
- **左侧**：商人库存（支持滚动）。
- **中间**：待换入 (Pending Receive) 和 待换出 (Pending Give) 槽位。
- **右侧**：玩家船只库存。
- **下方**：交易天平进度条和确认按钮。

#### 功能
- **选择数量**：点击库存格显示滑块面板选择数量。
- **交换逻辑**：玩家用物品（含金币）换取商人持有的物品。
- **价值天平**：实时计算双方价值，仅当玩家提供的价值 ≥ 商人提供的价值时可成交。
- **库存叠加**：多次点击同一物品可叠加 pending 数量。

### 港口选择对话框（_MapPortSelectDialog）
显示交互式的世界地图，用于选择航行目的地。

#### 界面构成
- **地图背景**: 使用 `world_map.png` (1344x768)，自动等比例缩放以适应屏幕。
- **港口标记**: 在地图上标记所有已解锁的港口位置（基于 `mapX`, `mapY`）。
- **交互反馈**: 
- **点击选择**: 点击港口图标即可选中目的地，选中的港口会显示红圈 (`red_circle.png`)。
- **悬停反馈**: 鼠标悬停在港口上方时，图标颜色会轻微变红以示可交互。
- **出发按钮**: 位于地图右下角，仅在选中目的地后可用，点击正式开始航行。
- **坐标调试**: 当调试开关开启时，地图上会额外显示跟随鼠标的十字准星和原始地图坐标数值。
- **状态标记**:
  - 当前港口使用橙色图标显示。
  - 其他可选择港口使用深褐色图标。
  - 任务系统支持：标记点集成 `QuestTarget`，支持教程引导。

#### 功能
- 显示所有已解锁的港口。
- **动态筛选**：当玩家处于海上状态时，自动隐藏“海上”地点和上一个出发的港口。
- **比例自适应**：地图与标记点坐标根据屏幕尺寸自动缩放。
- 点击“出发”按钮开始航行。

## 2.5.5 动画效果

### 岛屿切换动画
- **类型**：滑入滑出动画（SlideTransition）
- **时长**：1500ms
- **效果**：
  - 当前岛屿向左滑出屏幕（Offset(-1.0, 0.0)）
  - 新岛屿从右侧滑入屏幕（Offset(1.0, 0.0) → Offset.zero）
- **曲线**：Curves.easeInOut

### 船只浮动动画
- **类型**：上下浮动（Transform.translate）
- **范围**：-5px 到 +5px
- **时长**：2秒循环
- **曲线**：Curves.easeInOut
- **位置**：屏幕中央，向下偏移100像素

### 调试面板展开/折叠
- **类型**：SizeTransition
- **时长**：300ms
- **曲线**：Curves.easeInOut

## 2.5.6 响应式设计与比例锁定

### 比例锁定 (ScaleWrapper)
游戏采用 **1920x1080** 作为标准设计分辨率，并通过全局 `ScaleWrapper` 组件实现自适应缩放。

- **全局包装**：在 `lib/main.dart` 中，整个 `MaterialApp` 的 `builder` 被 `ScaleWrapper` 包裹。
- **功能**：
  - **等比例缩放**：根据当前窗口尺寸，计算与 1920x1080 的缩放比，使用 `FittedBox` 保持内容比例。
  - **纵横比锁定**：锁定 16:9，超出部分填充指定背景色（默认为黑色）。
  - **坐标系一致性**：通过覆盖子树的 `MediaQuery`，使所有子组件（包括对话框）感知到的屏幕尺寸均为 1920x1080，极大地简化了 UI 布局。
- **对话框简化**：由于有了全局缩放，各个对话框（如 `TradeDialog`, `SettingsDialog`）无需再单独包裹 `ScaleWrapper`，减少了嵌套层级。

### 自适应字体大小
部分基础组件（如状态栏）在 `ScaleWrapper` 内部仍会根据相对比例微调：
```dart
final fontSize = (screenWidth / 25).clamp(14.0, 18.0);
final iconSize = (screenWidth / 35).clamp(18.0, 22.0);
```

### SafeArea 支持
状态栏和时间显示使用 `SafeArea` 包裹，确保在不同设备的异形屏下内容不被遮挡。

## 2.5.7 按钮显示逻辑

### 显示条件
岛屿周围按钮仅在以下条件同时满足时显示：
- `!isTransitioning`：不在切换动画中
- `!isAtSea`：不在海上
- `currentPort != null`：当前有港口

### 延迟显示
入港后额外等待200ms确保动画完全结束，避免按钮在动画过程中显示。

## 2.5.9 交互流程

### 交易流程
1. 玩家在港口 → 点击"市场"按钮
2. 打开交易对话框 → 查看商品价格
3. 选择商品 → 点击"买"或"卖"按钮
4. 输入数量 → 确认交易
5. 更新状态 → 关闭对话框

### 航行流程
1. 玩家在港口或在海上（无目标港口）→ 点击"选择目的地"按钮
2. 打开港口选择对话框 → 查看可访问港口（包括"海上"特殊地点）
3. 在地图上点击选择目标港口 → 点击右下角"出发"按钮
4. 关闭对话框 → 开始航行动画（选择"海上"时立即进入海上状态，无进度条）
5. 显示航行进度条（仅在有目标港口时）→ 到达目的地

### 船员管理流程
1. 玩家在港口 → 点击"船员管理"按钮
2. 打开船员管理对话框 → 查看当前船员
3. 调整职业分配 → 通过下拉菜单选择
4. 查看效果变化 → 加成值实时更新
5. 确认更改 → 关闭对话框

## 2.5.10 样式规范

### 颜色方案
- **纸张底色**: 浅米色/棕褐色（由图片素材提供）
- **主要文本**: 深褐色 (`0xFF4E342E`)，用于模拟墨水效果
- **辅助说明**: 中褐色 (`0xFF5D4037`)
- **边框/分割线**: 浅咖啡色 (`0xFF8D6E63`)
- **功能色**（在纸张上进行调色处理）：
  - **蓝色**: 市场价值、载货量提示
  - **绿色**: 玩家获得、目的地
  - **红色**: 偏向商人、血条、关闭按钮
  - **黄色**: 税收、金币数值

### 字体规范
- **主要字体**：`ArkPixel` (方舟像素字体)，用于全游戏的文字显示，确保像素艺术风格的一致性。
- **标题**：20-22px，粗体
- **正文**：14-16px，常规
- **小字**：10-12px，常规
- **按钮文字**：16px，粗体
- **特殊字体**：调试面板中的技术数据同样使用 `ArkPixel` 替代系统默认等宽字体，保持视觉风格统一。
- **多语言支持**：通过配置 `ArkPixel` 的不同语言子集（zh_cn, ja, ko, latin 等），确保在全球化环境下文字显示的对齐与清晰度。

### 间距规范
- **内边距**：12-16px
- **外边距**：8-16px
- **按钮间距**：8px
- **列表项间距**：4px

### 圆角规范
- **对话框**：16px
- **按钮**：8px
- **卡片**：8px
- **状态栏**：12px（顶部）

## 2.5.11 应用程序图标 (Application Icon)

游戏使用统一的图标资产进行多平台适配：

## 2.5.12 子系统集成 (Sub-systems Integration)

UI 层集成了多个专门的逻辑子系统，以提供反馈和引导。

### 1. 提示系统 (Notification System)
用于向玩家展示即时的游戏反馈（如到港提醒、战斗开始、工资结算等）。提示显示在屏幕右上角，支持多重平滑叠加。
- 详细设计请参考：[2.17_notification_system.md](2.17_notification_system.md)

### 2. 任务与引导系统 (Quest System)
任务系统驱动教程引导，提供视觉指引（高亮遮罩）和交互限制（强制任务模式）。
- **QuestOverlay**: 位于应用根层级（`MaterialApp.builder`）的全屏层，负责绘制高亮遮罩和任务描述。由于其层级高于 `Navigator`，因此能够覆盖在所有弹出对话框之上。
- **交互控制**: 支持强制任务模式，确保玩家完成指定操作。
- 详细设计请参考：[2.16_quest_system.md](2.16_quest_system.md)

## 2.5.12 性能优化

### 图片加载
- 使用`gaplessPlayback: true`避免切换时的闪烁
- 使用`filterQuality: FilterQuality.medium`优化性能
- 提供错误处理，加载失败时显示备用UI

### 动画优化
- 使用`AnimatedBuilder`和`AnimatedSwitcher`优化动画性能
- 缓存计算结果，避免重复计算
- 使用`SingleTickerProviderStateMixin`管理动画控制器

### 列表优化
- 使用`ListView.builder`实现虚拟滚动
- 限制对话框最大高度，避免溢出
- 使用`Flexible`和`Expanded`实现响应式布局
